## データと表示の契約

### 入力を受け取る境界

`Usage` は次の項目だけを持つ。上流の `validateUsage` と同じ制約をTypeScript側にも持ち、合成入力で一致を確認する。上流の実行コードをHTTP経由でimportしない。

- `schemaVersion`、`generatedAt`、`collectors`、`sources`、`daily`、任意の `longestRun`、`snapshots`。
- ツールは `claude-code`、`codex`、`cursor`。Macは `air`、`m1`。snapshotの4種類と出どころも上流と同じ。
- 未知のキーを各階層で拒否する。トークン数と秒数は0以上の安全な整数。実在する日付、タイムゾーン付き時刻、coverageの順序、日別行の昇順・重複なし、トークンのcoverage内所属を確認する。
- `sources.coverage` は複数Macの期間の外枠で、途中の欠測を保証しない。日別行の欠落やツールのキー欠落を、期間内だからという理由で0に変えない。
- 不正な入力を一部だけ採用しない。上流に新しいツールやschemaVersionが出た場合は、既存の検証済みデータを表示し、対応範囲を見直す。

### 取得と控え

- Server Componentから固定の公開URLへ取得する。ブラウザからGitHubへのfetch、認証トークン、毎日のbioへの自動コミットは不要。
- `unstable_cache` で「取得 → JSON解析 → 検証」の成功結果を1時間保持する。内部のfetchは `cache: "no-store"` とし、二重のキャッシュ期限を設けない。取得は5秒でタイムアウトする。
- HTTPエラー、壊れたJSON、スキーマ違反はキャッシュ関数の中でthrowする。そこで空配列や控えを返すと正常データを上書きするため、行わない。
- 既存キャッシュがあればNext.jsの再検証失敗時の保持を使う。初回の取得失敗はキャッシュ関数の外で捕捉し、検証済みの `content/usage-fallback.json` を読む。控えも無効なら利用データだけ取得不可にし、プロフィールや連絡先は表示する。
- 控えは実装時の公開データを取得・検証したもの。元の `generatedAt` を保存し、取得日を新しいデータ更新日として書き換えない。テスト用の草を本番に入れない。
- 取得できるのはアクセスに応じた再検証。1時間ごとの定時取得や、常に1時間以内の反映は保証しない。再検証直後の次のリクエストで更新されることを確認する。
- モジュール変数のメモリだけを「前回成功した控え」にしない。Vercelの別プロセスや再デプロイで失われるため。
- 状態は `remote-cache` / `bundled` / `unavailable` と、データ自身の日時から作る。キャッシュが返っただけで「今回の取得成功」「最新」と表示しない。

Next.js 15の資料: https://nextjs.org/docs/15/app/api-reference/functions/unstable_cache 。計画時にはインストール済みの `node_modules/next/dist/server/web/spec-extension/unstable-cache.js` でも、App Routerの再検証失敗時に以前の値を返す処理を確認した。実装ではこの内部ファイルをimportせず公開APIを使う。

### 数字の定義

すべてAsia/Tokyoで日付を扱う。ブラウザのタイムゾーンで日付をずらさない。`today` はサーバーで一度決めて計算と初回描画へ渡し、取得キャッシュの中に固定しない。

| 表示 | 定義 |
|---|---|
| Total tokens | 今日までの全履歴の取得分を合算。草の53週には限定しない |
| Peak tokens | 今日までの1日合計の最大。日付も付ける。同値なら最も古い日 |
| Longest run | 入力の `longestRun` がactiveのときだけ表示。秒数・ツール・日付を使う。rawしかない場合は `—` と「対象の記録なし」にする |
| Longest streak | 今日までの1トークン以上使った日の最大連続日数。途中の欠落日・未取得日は切る |
| Current streak | 今日が正なら今日まで、今日が0またはまだ未取得なら昨日まで。昨日以前の取得も止まっている場合は0と断定せず `—` |

少なくとも1ツールが正なら、その日は利用あり。既知のツールがすべて0でも未取得があれば、利用なしと断定せず連続日数は切る。対象は `sources` にあるツールで、まだ取り込みを始めていないCursorを暗黙の0として足さない。

数字の帯は全ツール・全履歴で固定する。ツールの絞り込みは草とその代替表だけに適用する。取得範囲と入出力・キャッシュを含む合計であることは、出典・凡例・詳細表示で読めるようにする。詳しい値は桁区切りで読め、表示を「億」などに丸めてもコピー・読み上げ用の値を失わない。

更新日時には `generatedAt` を使い、詳細に各 `collectedAt` を出す。どちらかのMacが36時間以上更新されていない、または必要なcollectorが欠ける場合は「一部の集計が更新されていません」と示す。Current streakは参考値に見せず `—` にする。他の取得済みの履歴は残す。当日分は途中であることを示す。

### 草と代替表

- 今週の日曜を含む53列×7行。未来の日付は空白。2026-11-17を今日にすると2025-11-16〜2026-11-21の371セルで、11/18以降は未来。
- `All` と取得済みツールで絞り込む。Cursorがなければ操作不能な「未取得」とするか、利用可能なフィルターから外して凡例に未取得を示す。
- 全ツール取得済みの0、すべて未取得、一部未取得、未来を区別する。一部取得の日は判明した合計を表示し、詳細に「一部未取得」を出す。全データがない場合は371個の0を描かない。
- 正の値だけを昇順に並べ、nearest-rankの25/50/75パーセンタイルで4段階にする。境界以下を小さい側へ入れる。全て同値なら正の点は同じ最大サイズ。ゼロは専用の最小表示、未取得は別の形にする。
- 絞り込み後の正の値で段階を再計算する。Allの色はその日の最大ツール。同値は `codex` → `claude-code` → `cursor` の固定順。色だけで意味を伝えず、ツール名・凡例・詳細を付ける。
- 点はhoverだけに依存せず、キーボードとタップで日付・ツール別合計を読めるようにする。矢印キーで移動する1つのフォーカス位置を使い、371個のTab移動を要求しない。
- 同じ絞り込みの月別表を出す。月ごとの合計に加え、取得日数と一部未取得の有無を示す。月の一部分しか表示期間に入らないときは「表示期間内」と分かる見出しにする。
- 390pxではグラフ部分だけ横スクロール可とし、ページ全体を横にはみ出させない。暗い背景・明るい背景の両方で点、凡例、フォーカスが見えること。

|---|---|---|
