## 意図

soichiroyoshimura.com を、転職や新規プロジェクト獲得の営業で使えるページにする。見た人に「AIをここまで使い込んでいる人なら、新しいモデルが出てもすぐこの水準で使うだろう」と思わせたい。同時に、キャリア・コーチング・写真・家族を残して、多角的な人だと伝える。

いまのページは bento 型で情報量はあるが、意味のない数字（Projects / 3、Family / 5）や固定値のグラフが混ざり、同じ内容が上下で2回出ている。これを整理し、実データに置き換える。

## ゴール

- 冒頭でアイコン・名前・@soichiyo と、AI利用の実績値（累計トークン、最大トークン、最長タスク、最長連続日数、現在の連続日数）を見せる。
- Claude Code・Codex・Cursor をまたいだ1年分の利用状況を、ツール別に色分けした草として見せる。
- Stack と Plugins を本物のロゴで並べる。
- Showcase（AIと一緒に作ったものの棚）を用意する。公開時は非表示にし、載せるものができたら出す。
- Writing を Zenn と note から自動で更新する。
- Stack・Plugins・Showcase の項目を、データを1件足すだけで追加できる。
- 今後の保守がしやすいコードにする。

## 非ゴール

- 案件ごとのトークン集計（案件名が漏れる恐れがあり、自動化もしにくい）。
- プラグイン一覧の自動取得（スキル名に会社名が含まれるため、手で選ぶ）。
- Cursor の自動取得（公式の個人向けAPIがない。月1回の手動取り込みにする）。
- 草の「週別」「累計」表示の切り替え（初版は日別とツール絞り込みだけ）。
- 複数ページ化、CMS導入、言語切り替え。

## やってはいけないこと

- 出どころのない数字やグラフを載せる。すべての数字に出どころと基準日を持たせる。
- 説明文で画面を埋める。見出しの下の説明文は置かない。
- プロジェクト名・ファイルパス・会話内容を外に出す。


## 利用データの仕組み

```
各 Mac（毎日1回）                            データ専用リポジトリ            サイト
ログを集計 → 非公開の台帳を更新 → 日別合計を書く → 全 Mac 分を足して usage.json → 定期的に読み直して表示
```

### 出どころ

| ツール | 取り方 | 備考 |
|---|---|---|
| Claude Code | 手元のログを ccusage で集計（自動） | |
| Codex | 手元のログを ccusage で集計（自動） | ccusage 側は実験的な対応。ログ形式が変わると止まる |
| Cursor | ダッシュボードのCSVを月1回取り込む（手動） | 公式の個人向けAPIがない |
| opencode / Hermes Agent | ccusage が読めれば足す | 初版では必須にしない |

### 外に出すもの

`usage.json` に書いてよいのは、下の「usage.json の形」にある項目だけ。プロジェクト名・パス・モデル別の内訳・会話内容・自由記述は出さない。形を1つの厳密なスキーマとして定義し、そこに無いキーや型の違う値があれば書き出しを止める。自動集計・Cursor の取り込み・手入力のすべてが、同じ検証を通ってから書き出される。

### usage.json の形（提案）

```json
{
  "generatedAt": "2026-11-16T03:00:00+09:00",
  "collector": { "ccusage": "固定した版の番号" },
  "sources": {
    "claude-code": { "mode": "auto", "coverage": [{ "from": "2026-08-20", "to": "2026-11-16" }] },
    "codex": { "mode": "auto", "coverage": [{ "from": "2026-06-01", "to": "2026-11-16" }] },
    "cursor": { "mode": "import", "coverage": [{ "from": "2026-10-01", "to": "2026-10-31" }] }
  },
  "daily": [
    { "date": "2026-11-15", "tokens": { "claude-code": 1200000, "codex": 0 } }
  ],
  "longestTask": { "seconds": 1560, "tool": "codex", "date": "2026-10-01" },
  "snapshots": [
    { "key": "skillsTried", "value": 265, "asOf": "2026-11-16", "source": "chatgpt-profile" }
  ]
}
```

- **未取得とゼロの区別**: `coverage` は、そのツールのデータを取得できている期間。`daily` の `tokens` には、その日が `coverage` に入っているツールだけを書く。キーがあって `0` なら「使っていない」、キーが無ければ「未取得」。
- **snapshots**: 自動で取れない数字を手入力する場所。`key` は決めた一覧（`skillsTried` `skillRuns` `topReasoningShare` `fastModeShare`）だけ、`value` は数値、`source` は `chatgpt-profile` か `manual` だけ。
- **トークンの数え方**: ccusage の版を固定し、その版がツールごとに出す合計値をそのまま使う。集計はツールを明示して1つずつ行う（まとめての集計は使わない）。版を上げるときは、同じ日の値が変わらないことを確かめる。
- 累計、最大、最長連続、現在の連続は、サイト側で `daily` から計算する。

### 更新の決まり

- 集計は、エージェントを動かしているすべての Mac で行う。Workspaces の決まりでは個人リポジトリの作業は既定で M1 側で動くので、手元の Mac だけ集計すると抜ける。
- 各 Mac に非公開の台帳を持つ。台帳は「ツール × セッション × 日付」ごとに、これまでに見えた最大のトークン数を覚える。台帳は外に出さない。
- 毎回、残っているログを集計し直して台帳を更新する（加算はしない）。同じ日に何度実行しても結果は同じになる。ログからセッションが消えても台帳の値は残り、新しく現れたセッションは足される。
- 各 Mac は、台帳を日付とツールで合計した値だけをデータ専用リポジトリに書く。サイト用の `usage.json` は、全 Mac の値を足して作る。
- 当日分は途中の値で、翌日以降の実行で確定する。
- 手で直した値はデータ専用リポジトリの `overrides.json` に書く。間違って大きい値が残ったときもここで直す。
- 優先順位は、手で直した値、取り込んだ値（Cursor）、自動集計の順。
- セッション単位の日別の値を取れないツールは、「ツール × 日付」ごとの最大値で代用する。その場合、同じ日にログの削除と追加が重なると追加分を取り逃す。これは限界として残す。

### 連続日数の数え方

- どれかのツールで1トークン以上使った日を「使った日」とする。
- 取得できているツールがすべてゼロで、未取得のツールがある日は、いったん切れた扱いにする。あとから取り込めば計算し直されてつながる。実際より多く見せない側に倒す。
- 今日がまだゼロでも、現在の連続日数は昨日までで数える。
- いちばん早い `coverage` の開始日より前には遡らない。

### 最長タスクの定義（未決定）

セッションの開始から最後の記録までの長さは使わない。放置や中断の時間が混ざるため（レビューで、約661時間・途中に約32時間の空白があるセッションが見つかった）。候補は次の2つ。

| 案 | 測るもの | 取り方 | 値（レビュー時点） |
|---|---|---|---|
| 1 | 1回の指示の開始から完了までの経過時間 | Codex の完了記録の `duration_ms`、Claude Code の `turn_duration.durationMs` | Codex の保存ログで最長 約85分 |
| 2 | ChatGPT プロフィールの「最長タスク」 | 手入力（`snapshots`） | 15時間30分 |

提案は案1。自動で取れて、指示と指示のあいだの放置時間が混ざらない。ただし稼働時間ではなく経過時間なので、1回の指示の中でエージェントが待機した時間は含まれる。数字は案2より小さくなる。案2は数え方が公開されておらず、クラウド側の実行を含む可能性がある。

### わかっている限界

- 手元のログに残る分しか数えられない。クラウド側で実行した分は入らないので、ChatGPT のプロフィールに出ている Codex の数字（累計 502.9億など）より小さく出る可能性がある。
- 集計を始める前の履歴は、手元に残っているログの範囲までしか遡れない。
- Mac を数日開かなければ更新が止まる。更新日を表示して隠さない。

## 設計側で決めたこと（要確認）
