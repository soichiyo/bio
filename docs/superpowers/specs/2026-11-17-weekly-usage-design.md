# Token usage を週別・合算にする 設計

Date: 2026-11-17

モック（承認済み）: https://claude.ai/artifact/7g8v8JBf8oAYPzMT8BHyWZ

親の設計書は `2026-11-16-ai-profile-redesign-design.md`。この文書は、その「Token usage」「数字の帯」「利用データの仕組み」のうち、下に書いた点だけを置き換える。「決定」は本人が会話で決めたこと、「提案」は設計側の判断。

## 意図

いまの Token usage は日別・ツール別で、2つの困りごとがある。

- 複数のツールを同じ日に使うと、点の色がどれか1つになり、合わせて使っている実態が伝わらない。
- 日別だと、使っていない日がそのまま見える。

## 決定

1. Token usage は全ツールを合算した1本にする。ツール別の色分けと絞り込みはやめる。
2. 日別ではなく週別にまとめる。
3. 表示する期間は直近26週（約半年）。
4. 丸1個 = 5億トークン。端数は切り上げる（3億なら1個、11億なら3個）。
5. 画面だけでなく、外に出すデータも週別だけにする。`soichiyo/ai-usage` を非公開にし、サイトは週別・合算に変換した数字だけを受け取る。

## ゴール

- ブラウザに届くデータ、bio リポジトリのコードと控えのどこにも、日別・ツール別の値が無い。
- モックの Token usage と数字の帯が、実データで本番に出る。
- 切り替えの途中で、利用データの表示が消えない。

## 非ゴール

- bio の git 履歴に残っている日別の控え（2026-11-17 まで）を消すこと。履歴は書き換えない。
- 集計の仕組み（各 Mac の launchd、ccusage、Mac ごとの日別ファイル）を変えること。非公開のリポジトリの中では日別のまま持つ。
- 旧デザインの変更。Cursor の取り込み。

## やってはいけないこと

- 鍵の値を、コード・ログ・エラー文・PR・チャットに出す。
- 非公開化を先にやって、サイトが控えの表示に落ちたままにする。

## 進め方（検討した案）

| 案 | 内容 | 得るもの | 失うもの |
|---|---|---|---|
| A | 画面だけ週別にする | 作業が小さい | 公開リポジトリと控えに日別が残る |
| B | `ai-usage` を非公開にし、週別の `weekly.json` だけをサイトが鍵つきで読む | 日別が外に出ない。リポジトリは1つのまま | Vercel に読み取り用の鍵が1つ要る。鍵の期限切れで更新が止まる |
| C | リポジトリは公開のまま、各 Mac が週別の値だけを push する | 鍵が要らない | 週の途中の値を毎日コミットするので、git の履歴の差分から日別の増分がわかる。既存の履歴も消す必要がある |

本人が B を選んだ。C は履歴から日別が読めるので、目的に合わない。

## 画面

**Token usage**

- 直近26週を、週ごとに1本の丸の柱で表す。左が古く、右端が今週。週は日曜始まり、日付の区切りは Asia/Tokyo。
- 丸の数は `ceil(その週のトークン数 ÷ 5億)`。0 の週は丸なし。
- 柱の高さは8段を基本にし、9個以上の週が出たらその数まで伸ばす。
- 丸は1色。今週の柱だけ薄い色にして、凡例に「集計中」と出す。
- 見出しの右に「Last 26 weeks · Weekly · All tools」。凡例は「● = 5億 tokens」。
- 丸を読めない人のために、週別の表（週の開始日、トークン数、丸の数）を開けるようにする。
- ツールの絞り込み、日ごとの詳細、月別の表は無くす。

**数字の帯**

| ラベル | 値 | 補足の行 |
|---|---|---|
| Total tokens | 全期間の合計（変更なし） | 取得した全履歴 |
| Peak week | 週の最大 | その週の開始日 |
| Longest run | 変更なし | ツール名と年月（日は出さない） |
| Longest streak | 連続して使った週数の最大 | 週 · 取得した全履歴 |
| Current streak | いま続いている週数 | 週 · 今週または先週まで |

- Total を直近26週ではなく全期間にするのは提案。差が小さく（377億と408億）、説明が1つ減る。
- 連続は、今週のトークンが1以上なら今週から、0 なら先週から遡って数える。データの最後の週が先週より古いときは「更新待ち」にする。

## データ

`ai-usage`（非公開）の GitHub Actions が、いまの `usage.json`（日別）に加えて `weekly.json` を作る。サイトが読むのは `weekly.json` だけ。

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-11-17T04:22:22.615Z",
  "collectors": [{ "machine": "air", "collectedAt": "2026-11-17T13:07:00+09:00" }],
  "tools": ["claude-code", "codex"],
  "coverage": { "from": "2025-09-14", "to": "2026-11-15" },
  "weeks": [{ "week": "2026-11-15", "tokens": 341144536 }],
  "longestRun": { "seconds": 47175, "tool": "codex", "week": "2026-09-06" },
  "snapshots": [{ "key": "skillsTried", "value": 265, "asOf": "2026-11-16", "source": "chatgpt-profile" }]
}
```

- `week` は週の開始日（日曜）。`weeks` は `coverage.from` から `coverage.to` まで、欠けなく1週1行。
- `tokens` は、その週の全ツール・全 Mac の合計。ツール別の値は入れない。
- `tools` は合計に含まれるツールの一覧。画面の出典の説明に使う。
- `longestRun` は、日ではなく週で持つ。`active` の値があるときだけ入れる。
- スキーマに無いキーがあれば、作る側も読む側も止める。

サイトは GitHub の API から `weekly.json` を取る。Vercel の環境変数 `AI_USAGE_TOKEN`（`ai-usage` の内容を読むだけの鍵）があれば、それを付ける。取得に失敗したら、bio に入れた週別の控えを出す。再取得の間隔は今と同じ1時間。

## 切り替えの順番

1. `ai-usage` が `weekly.json` を作り始める（まだ公開のまま）。
2. bio が `weekly.json` を読む新しい画面を本番に出す。控えも週別に替える。
3. 本人が鍵を作り、Vercel に入れる。
4. `ai-usage` を非公開にする。
5. 集計を1回動かし、サイトの更新時刻が新しくなることを確かめる。ならなければ公開に戻す。

## 設計側で決めたこと（要確認）

- Total tokens は全期間のまま。
- Longest run の補足は年月まで。
- 週別の表を残す（月別の表の代わり）。
- 鍵が無い環境（CI、手元）では、鍵なしで取得を試み、失敗したら控えを出す。
- 親の設計書の該当箇所には、この文書への案内を1行ずつ足す。本文は書き換えない。

## 残る限界

- bio の git 履歴には、2026-11-17 までの日別の控えが残る。
- 今週の柱は毎日伸びる。毎日ページを見比べれば、日ごとの増分は推測できる。
- 鍵に期限がある場合、切れると更新が止まり、控えの表示になる。期限を README に書いておく。
